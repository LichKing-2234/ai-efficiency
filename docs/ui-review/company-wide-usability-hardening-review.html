Current Audit

优先级最高的问题

这些不是视觉偏好，而是会直接影响用户能否完成任务的问题。

High

移动端仍像压缩后的桌面后台

/user 有页面级横向溢出；使用记录、仓库、仓库详情和管理后台依赖横向表格。移动端必须改成卡片或关键列优先。

High

“我的接入”不是 onboarding，而是命令手册

用户需要先理解 CLI、hooks、provider、group、API key、doctor，才能判断下一步。目标应改成进度流：已完成什么、下一步做什么、失败找谁。

Medium

中文模式仍暴露未治理英文标签

Group:、Platform:、API KEY、PROMPT、BASE URL、Path 等需要归入术语合同。

Medium

弹层、抽屉和行详情缺少可访问性合同

移动菜单、事件详情、添加仓库和设置弹窗需要 dialog 语义、焦点管理、Escape 关闭和键盘等价操作。

Target Experience

目标状态：任务优先，而不是资源优先

保留现有路由和后端合同，但每个页面的第一屏都先回答用户问题。

移动端验收规则

375px 宽度下，不允许页面级横向滚动；主操作必须可见；长字段进入详情或高级区。

禁止主流程横向表格 卡片优先 详情抽屉 raw 明细可横向滚动
Setup Flow

“我的接入”改成进度流

命令仍然存在，但从首屏主角变成每一步的可复制操作。

1. 状态

账号、AI 接入、工具配置、Git 上报、仓库诊断分别给出已完成/待处理/需要帮助。

2. 操作

每一步只有一个主操作：复制安装命令、复制登录命令、复制配置命令、查看诊断命令。

3. 高级

API key、provider test、manual sync、hook upload status 放进高级折叠区，并保留风险确认。

Terminology

多语言不是翻译所有技术词

用户界面要本地化，命令、模型名、仓库名、provider display name 和 commit SHA 保持原样。

Acceptance

进入实现阶段的验收清单

这些标准应写入实现 plan，而不是只停留在设计建议。

响应式

375px / 390px / 768px / 1280px / 1440px 页面无主流程横向溢出。

双语

被触达页面的主标题、按钮、空态、错误、风险提示都有 en-US 与 zh-CN。

可访问性

移动菜单、详情抽屉、设置弹窗都有 dialog 语义、焦点管理、Escape 关闭。

URL 可恢复

使用记录筛选、仓库绑定筛选、管理后台 tab、用户管理搜索分页可通过 URL 恢复。
