登录与授权

登录、OAuth 授权、Device Login 是同一套 Auth Experience，不应一个英文、一个中文、一个 demo 风格。

/login

统一品牌、语言切换、LDAP/SSO 解释。Auth Source 不作为普通用户优先理解项，默认由系统选推荐方式。

/oauth/authorize

显示“哪个客户端请求什么权限、授权后会发生什么”，拒绝和授权按钮同层级但主次清晰。

/oauth/device

围绕 CLI 设备登录：输入码、确认账号、授权结果、回到终端。与 `/user` 的命令引导互相衔接。

分阶段落地建议

不建议一次性把所有历史页面全重写。按用户价值和风险拆成 4 个阶段，每阶段都能单独测试和 review。

Phase 1 · Shell + 普通入口
  • 导航分组
  • 首页增强
  • /user 渐进披露
  • /events 摘要列表
Phase 2 · 代码与 PR
  • /repos 健康度工作台
  • /repos/:id PR freshness
  • 高密度表格进入高级区
Phase 3 · 管理后台拆分
  • Settings 组件拆分
  • AI 服务 / SCM / LDAP / Deploy tabs
  • 风险操作确认
Phase 4 · Auth 体验统一
  • Login 本地化
  • OAuth 授权页统一
  • Device Login 与 CLI 引导衔接
推荐先把本 HTML review 收敛成 spec，然后写实现 plan。实现时优先不改 API，只重组前端组件和文案；如果发现缺少个人维度数据，再单独扩展薄聚合 API。
